# Package API / UI integration review

Reviewed on 2026-10-26. Integration base: `feat/design-refresh` at `5f10484b90eb1215f2d767b5fe746f7c2b01caa3`.
Includes PR #3 (`e1686d77d0f3c262ba98da7aaf18e73d197c1714`) and PR #4 (`2649e76373407d292f8f8f28b6f3d988b917981f`) for integrated review; their original branches are not merged by this change.

## Implemented

- Package lists consume the package API, retain its global rank and order, and paginate using one snapshot. Unlinked findings remain separately visible. Processing, failed and unavailable states are not represented as zero findings.
- Package details use stable group IDs, preserve installation-specific candidates and provenance, and display unknown whole-package remediation rather than infer a common safe version.
- Correction prompts serialize allowed fields from the full detail response, including every finding and installation link, UNKNOWN and low severity findings, and findings without candidates. Partial results and review status remain explicit. Original free-form evidence/descriptions are excluded.
- Copy revalidates the snapshot. A 409 requires refresh; it cannot silently copy mixed snapshots. Existing package AI explanation remains separate from the correction prompt and is not generated by copying it.
- Legacy name/version links resolve only when exactly one current package group matches. Finding detail links remain available for existing dependency-path views.
